generate_symbol_table.py 技術說明

從 Slot 分類結果中的 Help / Paytable 截圖，自動找出 Symbol 賠率頁、裁切 Symbol Icon， 並產出可供競品研究使用的 Symbol Table HTML。現在已接入 main.py 分類流程， 跑 input 影片時可同步輸出遊戲畫面與 symbol 圖。工具目前以 OpenCV 與 OCR 為主， Claude / Haiku 僅作為可選的辨識與 fallback。

最後更新：2026-05-15 主流程：main.py 分類 + Symbol icon export 路徑：slot_classifier_figma_share_package/app 可用 bat 一鍵執行

工具定位

generate_symbol_table.py 是接在 main.py 影片截圖分類流程後面的 Symbol 資料整理工具。 main.py 負責從影片擷取並分類遊戲畫面；本工具則進一步處理 Help / Paytable 頁， 將賠率頁中的 symbol 圖示裁切出來，整理成 HTML 報告與可重用的圖像素材。

2026-05-15 起，main.py 已可在單一流程中完成「影片分類」與「symbol 圖輸出」： 每支影片分類完成後，會直接以該遊戲的 project/output/<video_id>/ 資料夾作為輸入， 執行本地 icon 匯出流程。

現在的方向是讓 OpenCV 負責「找位置與裁切」，OCR 負責「判斷頁面文字線索」。 AI 主要保留在「symbol 命名、賠率理解、競品報告整理」這類需要語意判斷的步驟， 以降低 API token 成本。

整體流程

1. 影片分類 main.py 讀取 input 影片，擷取 ROI，依 OCR 與畫面特徵分類成 Help、Basegame、BigWin、Feature game 等資料夾。
2. 收集 Help 圖片 同時讀取 final Help 與 low_score/Help， 避免 Paytable 因最後取樣不足而漏掉。
3. Paytable 預篩 OpenCV 先判斷畫面是否像賠率頁；通過後才執行 OCR，減少整批 Help 逐張 OCR 的成本。
4. Symbol 裁切 使用 connected components 找獨立彩色圖示，並結合舊有 PG 兩欄式 layout fallback。
5. HTML 與圖檔產出 產出 symbol table、Help 縮圖、debug 頁面與可人工檢查的裁切圖。

與 main.py 整合後的流程

原本 main.py 與 generate_symbol_table.py 需要分開執行。現在整合後， main.py 會在每支影片分類完成、執行 keep_selected_images() 後， 直接呼叫 generate_symbols_for_output()，再由該函式載入 generate_symbol_table.py 的 process_video()。

節點 行為
分類輸出 main.py 產生 Help、Basegame、Feature game 等分類資料夾與 CSV。
Help 去重 Help 選圖加入視覺相似度檢查，降低同一頁不同幀重複保留的問題。
Symbol 匯出 以同一個 project/output/<video_id>/ 作為輸入，使用 icons_only=True 產生最終 symbol 圖。
CLI 控制 --skip-symbols 可跳過 symbol 匯出；--symbol-debug 可輸出額外 debug 圖。

Paytable 偵測設計

Paytable 偵測採兩階段：先用影像特徵快速預篩，再用 OCR 做文字確認。 這能保留「不用 API key 也能跑」的能力，同時避免把所有 Help 頁都丟給 AI。

目前在 icon export 模式下，Paytable 掃描會保留較多候選頁，並避免只取最高分頁面。 對滾動式 Help 而言，不同 symbol 往往分布在不同幀，序列抽樣可降低 Q、單一特殊 symbol 或低頻 symbol 被漏掉的風險。

階段 技術 判斷重點
CV 預篩 OpenCV / connected components 深色說明背景、彩色 icon 群、黃白色賠率文字、圖示分布密度。
OCR 確認 PaddleOCR Paytable、Symbol Payout、Wild、Scatter、Full、數字賠率、3 - 50 類型 payout pair。
AI fallback Claude Haiku 本地 CV + OCR 找不到 Paytable 時，才用 Haiku 判斷 Help 頁是否為 Symbol Paytable。

Symbol 裁切策略

通用偵測

  • 用 connected components 找獨立彩色圖示。
  • 過濾純數字、純文字、過扁、過小或過大的候選框。
  • 針對右側 payout number column 做後處理，避免 symbol 右側黏到賠率數字。
  • 裁切邊界加入適度 padding，避免壽司、鼓、招財貓等 symbol 被切到邊。
  • 加入主 artwork component 二次裁切，盡量保留完整圖示並降低半截圖進入 final set。

相容策略

  • 保留 PG / Lucky Neko 這類兩欄式 Paytable 的舊版 layout 偵測作為 fallback。
  • Web-style Help 若是寬版網頁，不強制裁成中間直式 dialog，避免左側內容被切掉。
  • 同一 symbol 先用 dHash 初篩，再用實際像素相似度確認，避免 Q 與相近圖示被誤合併。
  • 最終候選排序會優先保留內容量較高、形狀較完整、貼邊風險較低的圖。

AI 使用位置

步驟 是否需要 API key 備註
Paytable 頁面預篩 不一定 優先使用 OpenCV + OCR；只有本地偵測失敗且未使用 --no-ai 時才 fallback 到 Haiku。
Symbol 座標裁切 不需要 由 OpenCV 處理，不再依賴 AI 回傳 crop coordinates。
Symbol 命名與賠率理解 需要 需要 Claude / Sonnet 判斷圖示語意、名稱、tier、賠率排序。
HTML 骨架與 debug 檢查 不需要 --no-ai 可跑本地流程，用於檢查 Paytable 與裁切品質。

常用指令

建議主流程

  • bash classify_with_roi_confirm.sh --video-id "PerfectStrike"：完整流程（ROI 確認 + 分類 + symbol 提取），推薦入口。
  • bash run_classify.sh：處理 project/input_videos/ 裡的全部影片，分類後同步輸出 symbol 圖（不含 ROI 確認）。
  • bash run_classify.sh --video-id "PerfectStrike"：只處理單一影片。
  • bash run_classify.sh --skip-symbols：只跑分類，不產生 symbol 圖。

Symbol 工具單獨執行

  • python app/generate_symbol_table.py：針對既有 project/output/ 處理全部影片資料夾。
  • python app/generate_symbol_table.py --video-id 8：只處理單一影片輸出資料夾。
  • python app/generate_symbol_table.py --debug：輸出 Paytable 候選與裁切框線 debug 檔。
  • python app/generate_symbol_table.py --with-ai --api-key sk-...：啟用舊版 Claude + HTML 語意流程。
