Slot 遊戲截圖分類工具技術總結

這個工具用來批次讀取遊戲錄影，自動擷取代表性截圖，並依照 slot 遊戲流程分類成 Basegame、Feature game、Big Win、Result、Transition、Help、Feature Buy、loading 與 Other。最新版已結合 symbol 裁切工具，跑完分類後會同步從 Help / Paytable 畫面輸出 symbol 圖，方便後續美術調研、競品整理、Figma / FigJam 視覺化與素材資料庫建立。

最後更新：2026-05-15 Python OpenCV PaddleOCR 影像特徵分群 批次影片處理 Symbol 圖自動裁切

工具目標

主要目標不是單純截圖，而是從大量錄影中整理出可供人工判讀與美術參考的「乾淨代表圖」。工具會盡量排除模糊、爆光、遮擋盤面、大範圍缺少細節、半透明文字雜訊過多的畫面，並把低信心圖片放進 low_score 供人工檢查。整合 symbol 裁切後，Help / Paytable 截圖也會被進一步轉成可檢查、可整理、可再利用的 symbol 圖。

批次處理

支援在 input 資料夾放入多支影片，輸出時依影片名稱建立各自的分類資料夾與 CSV。

研究導向

最後保留的圖片用於調研與 Figma 整理，因此分類重視「能代表該狀態」而不是只追求最高 OCR 分數。

Symbol 素材化

分類後會自動掃描 Help / Paytable 頁，輸出 symbol_table/symbols 與 contact sheet，讓 symbol 圖能直接進入後續競品素材整理。

一鍵執行

新增 run_classify_and_symbols.bat，可雙擊跑全部影片，也可用影片名稱只跑單一遊戲。

處理流程

1. 讀取影片 逐支讀取 input videos，依取樣間隔擷取候選影格。
2. Auto ROI 自動偵測遊戲畫面區域，避免瀏覽器外框與背景干擾。
3. 前處理過濾 排除模糊、過曝、低差異、噪聲與畫面重複度太高的截圖。
4. OCR + 視覺判斷 讀取畫面文字，搭配 OpenCV UI 特徵分數進行分類。
5. 代表圖挑選 透過分數、分群與品質規則，輸出最適合調研的代表圖。
6. Symbol 裁切 從 Help / Paytable 圖自動找 symbol，輸出 symbol PNG、HTML 與 contact sheet。

整合 symbol 裁切後的用途

遊戲流程研究

分類後的 Basegame、Feature game、Transition、Result、BigWin 等代表圖，可用來快速理解一款 slot 的主要流程與視覺節奏。

Help / 規則整理

Help 圖會保留規則與 paytable 內容，並透過視覺去重降低同一頁不同幀重複出現。

Symbol 素材資料庫

Paytable 中的 symbol 會被裁切成獨立 PNG，集中到 symbol_table/symbols，方便後續命名、分級、比較與素材盤點。

競品報告與 Figma 看板

分類截圖與 symbol 圖可共同作為競品報告素材，減少人工逐幀截圖、整理與搬圖的時間。

主要技術

技術 用途
OpenCV 影片讀取、畫面裁切、動態偵測、亮度/飽和度/邊緣分析、圓形按鈕偵測、底部 UI 顏色與結構判斷。
PaddleOCR 辨識畫面上的遊戲文字，例如 Free Game、Total Win、Big Win、Feature Buy、Paytable、Loading 與廠商授權資訊。
規則式分類 把 OCR 關鍵字、文字位置、UI 分數、畫面品質分數整合成分類分數，處理不同廠家畫面差異。
影像品質評分 偵測爆光、模糊、半透明文字疊影、大色塊缺少細節與盤面遮擋，避免髒圖進入最終資料夾。
視覺分群 在 Basegame、Feature game、Big Win 等類別中用影像特徵做群聚，挑出有代表性的不同狀態。
Help 視覺去重 使用縮圖差異與色彩直方圖相似度判斷 Help 畫面是否重複，降低同頁不同幀重複保留。
Symbol 裁切 分類完成後接續呼叫 generate_symbol_table.py，從 Paytable 頁偵測 symbol component，輸出獨立 PNG 與 contact sheet。

分類類別

類別 判斷重點
loading 遊戲封面、遊戲 logo、廠家名稱、授權/認證/版權文字、進度條、GET STARTED 等載入頁特徵。
Basegame 明確底部遊戲 UI，尤其是 spin 按鈕、auto、turbo、加減注、金額欄位與控制按鈕組合。新版已收緊，避免把非主流小遊戲或單純 WIN 畫面誤判成 Basegame。
Feature game Running 狀態優先，例如 Remaining Free Spins、Free Game 10/10、Last Free Spin 等；同時保留廠家特例：base/free UI 相近時，會用底部 UI 與 free game 計數再判斷。
Transition Free Spins 開始頁、Start/Continue/Confirm 等轉場畫面。若畫面其實是封面 loading、Help 規則頁或 Feature Buy 彈窗，會被優先改分到對應類別。
Result Total Win、Collect、You've won 等結算畫面，以及置中大型得分。
BigWin Big Win、Mega Win、Super Mega Win、Super Win、Jumbo Win 等多階大獎字樣與大型分數。最後取樣會盡量保留不同階段的大獎代表圖。
Feature Buy 大型購買功能彈窗，通常含 Feature Buy / Buy Feature、Cost、Bet、Quantity、Start、Cancel、Buy 等文字。一般 Basegame 中固定的 buy feature 小按鈕不會直接算 Feature Buy。
Help 規則說明、Paytable、Symbol Payout Values、Game Feature、Jackpot、Paylines 等大量文字頁。網頁式 Help 會盡量使用整頁裁切，保留完整規則內容；Paytable 類 Help 也是後續 symbol 裁切的主要來源。
Other 品牌 logo 全頁、非主流小遊戲、阻擋彈窗、無法穩定歸類或不適合調研的畫面。

Auto ROI 裁切

Auto ROI 會用畫面動態區域、比例、瀏覽器頂部裁切與特殊網頁 Help 偵測來推估真正的遊戲區域。對直式手機遊戲、橫式遊戲、網頁切版 Help 頁都有對應保護。

  • 直式遊戲：避免把左右背景一起裁進去，讓 OCR 更集中在遊戲畫面。
  • 橫式遊戲：避免因背景動態太大導致 ROI 過寬。
  • 網頁 Help：若偵測到大範圍規則頁，會改用完整網頁內容裁切，而不是只裁遊戲 iframe。

品質過濾與代表圖挑選

分類後並不會直接把所有圖片放進最終資料夾。工具會再依照該類別的特性挑選較乾淨的圖片，並把不確定或品質較差的圖片放進 low_score。

會被降低優先度的圖

  • 動態模糊明顯
  • 大範圍爆光且缺少細節
  • 盤面被角色、彈窗或特效遮住
  • 半透明文字或轉場殘影太多
  • 與其他圖片重複度太高
  • Help 頁若只是相同畫面的不同幀，會降低保留優先度

會被提高優先度的圖

  • 盤面完整清楚
  • UI 狀態明確
  • OCR 可讀性高
  • 能代表該類別核心狀態
  • Big Win 可代表不同大獎階段
  • Help / Paytable 頁能提供 symbol 裁切來源

目前模組架構

主程式仍保留 main.py 作為入口，但已開始拆分模組，降低後續維護成本。

檔案 責任
main.py 分類邏輯、品質評分、代表圖挑選、整體流程控制；分類完成後可自動呼叫 symbol 裁切流程。
config.py 路徑、分類名稱、影片副檔名與 Auto ROI 相關常數。
video_io.py 影片列表、輸出資料夾、圖片讀寫、CSV 寫入等 I/O 工作。
ocr_utils.py PaddleOCR 初始化、OCR 執行與結果解析。
auto_roi.py 遊戲畫面自動裁切、網頁 Help 全頁 ROI、橫式/直式裁切策略。
analysis_export.py 讀取分類結果，匯出玩法分析、流程摘要與 HTML/JSON/Markdown 研究資料。
generate_symbol_table.py 從分類後的 Help / Paytable 圖中偵測 paytable 頁與 symbol component，輸出 symbol_table/symbols、HTML 與 contact sheet。
run_classify_and_symbols.bat 提供非工程使用者可直接執行的入口：雙擊跑全部 input 影片，或用影片名稱指定單一遊戲。

使用方式與輸出位置

主要執行方式

  • run_classify_and_symbols.bat：處理 project/input_videos/ 內全部影片。
  • run_classify_and_symbols.bat "Perfect Strike"：只處理指定影片，名稱對應影片檔名 stem。
  • run_classify_and_symbols.bat --skip-symbols：只輸出分類截圖，不產生 symbol 圖。
  • run_classify_and_symbols.bat --video-id "Perfect Strike" --symbol-debug：指定影片並輸出 symbol debug 圖。

主要輸出

  • project/output/<video_id>/<分類>/：分類後的代表截圖。
  • classification_result.csv：每張候選截圖的分類、OCR 與分數記錄。
  • symbol_table/symbols/：最終 symbol PNG。
  • symbol_table/final_icons_contact_sheet.jpg：symbol 圖總覽，方便人工快速檢查。

Figma / FigJam 整合方向

分類完成後，工具可產出 Figma 匯入用資料，讓每支影片保留代表性截圖並排成研究看板。整合 symbol 裁切後，symbol 圖也能作為獨立素材進入競品看板或後續報告。為了避免 MCP tool call limit，流程設計成「本地先生成 manifest 與素材清單，再由 Figma plugin 一次讀入」。

  • 各影片保留 Basegame、Feature game、loading、Result、Transition、Help、Feature Buy 等代表圖。
  • Big Win 盡量保留多階大獎圖，例如 Big Win、Mega Win、Super Mega Win、Super Win、Jumbo Win。
  • Other 通常不進研究看板，除非人工後續需要。
  • Help 圖可提供 AI 或人工閱讀規則，作為玩法分析與競品拆解基礎。
  • Symbol 圖可獨立整理成 icon board，用於比較不同遊戲的高低階符號、特殊符號與美術風格。

目前限制與後續方向

這套分類目前以主流 iGaming slot 流程為基礎：Basegame → Transition → Feature game → Result。若遊戲的 Feature 是足球、卡牌、輪盤或其他小遊戲形式，可能不應硬歸到原本的 Feature game，而是先放入 Other 或後續新增子類別。

  • 持續拆分 main.py，把分類規則、品質分數、代表圖挑選與 symbol pipeline 入口各自模組化。
  • 加強不同廠家的 UI 特徵，例如 FC、PG、Omniplay、YB 網頁 Help 等。
  • 持續優化 Help 選圖，降低滾動式 Help 中同頁不同幀重複保留，同時避免 Paytable 頁漏掉。
  • 針對 symbol 旁有 payout 數字的版面，進一步做「去數字但保留完整 symbol」裁切。
  • 改善 Big Win 多階段取樣，從 OCR 直接區分 Big/Mega/Super/Jumbo 等大獎層級。
  • 讓 Figma 匯入流程更自動化，減少手動複製 plugin 資料的步驟，並支援分類截圖與 symbol 圖一起進入看板。

給 coworker 的一句話版本

這是一個結合 OpenCV 與 OCR 的 slot 影片分類與 symbol 擷取工具：它會自動找到遊戲畫面、擷取關鍵影格、判斷遊戲流程狀態、過濾髒圖，並從 Help / Paytable 中裁出 symbol 圖，最後輸出可直接用於美術調研、競品報告與 Figma 看板整理的素材。
